## 模块接口约定

- `pmm.c` 通过 `pmm_manager` 的 `init`、`init_memmap`、`alloc_pages`、`free_pages`、`nr_free_pages`、`check` 调用分配器；Best-Fit 实现必须完整提供这些函数指针。
- `page_init()` 使用 `get_memory_base()`、`get_memory_size()` 获取物理内存范围，并只把真正可分配的页传给 `init_memmap()`；`pages` 数组与内核本身占用的页必须保留。
- Best-Fit 的空闲块以 `struct Page` 的 `property` 表示长度，以 `PG_property` 标记块首；`nr_free_pages()` 返回空闲**页数**，而不是空闲块数。
- 调试时可参考 `default_pmm.c` 的链表、拆分和合并逻辑，但最终选块必须遵循最佳适应规则。

```bash

```

预期看到内核 `check_alloc_page() succeeded!`，且评分输出包含：

```text
[Test 1] Page Init: PASS
[Test 2] Best-Fit: PASS
```

评分脚本会将源码复制到临时目录，再注入测试；不要把注入后的文件复制回开发目录。若编译失败，先看是 `pmm.c` 还是 `best_fit_pmm.c`；若运行时断言失败，再检查页保留范围、空闲页计数、最小块选择和相邻块合并。
