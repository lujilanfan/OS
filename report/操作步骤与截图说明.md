## 2. 构建、ELF 和裸镜像

```sh
make clean
make
ls -lh bin/kernel bin/ucore.img
file bin/kernel bin/ucore.img
riscv64-unknown-elf-readelf -h bin/kernel
riscv64-unknown-elf-readelf -S bin/kernel
riscv64-unknown-elf-nm -n bin/kernel | grep -E 'kern_entry|kern_init|bootstack|bootstacktop|edata|end'
riscv64-unknown-elf-objdump -d bin/kernel | sed -n '/<kern_entry>:/,+8p'
sha256sum bin/kernel bin/ucore.img
```

核对：ELF 入口 `0x80200000`；`bootstack=0x80201000`、`bootstacktop=0x80203000`，相差 `0x2000=8192` 字节；本次 `edata=end=0x80203008`。`bin/ucore.img` 是裸字节镜像，没有 ELF 文件头。若跨 Windows/WSL 目录出现亚秒级 `Clock skew` 提示，还要看退出码、完整重建、镜像和启动是否成功；本机先前已用后续启动/GDB 复核。

**你截 `02-编译产物.png` 和 `03-ELF与符号.png`：** 展示真实 `make` 成功、两个产物、ELF 入口及栈符号。按实际画面拆图即可。

## 4. 用两个终端执行练习 2

先确认上一节 QEMU 已退出。终端 A 在同一 `code/` 执行：

```sh
make debug QEMU=/home/lxj/.local/opt/qemu-4.1.1/bin/qemu-system-riscv64
```

它使用原始 `-device loader,file=bin/ucore.img,addr=0x80200000`，再加 `-s -S`：开放本机 GDB 1234 端口，并在第一条指令前暂停。终端 B 在同一 `code/` 执行：

```sh
gdb-multiarch bin/kernel
```

在终端 B 的 GDB 输入：

```gdb
set pagination off
set architecture riscv:rv64
target remote localhost:1234
display/i $pc
p/x $pc
x/5i $pc
x/16bx 0x80200000
```

初始 PC 应为 `0x1000`。此时内核入口已经有机器码；另开一个 Bash 终端运行 `od -An -tx1 -N16 bin/ucore.img`，对照开头 16 字节。说明 QEMU 在虚拟 CPU 开始前已把镜像放入内存。**你截 `05-复位与预装载.png`：** PC、五条复位指令、内核入口内存；镜像字节对照可另截一张。

接着逐条执行，不要一次粘贴所有 `si`：

```gdb
si
info registers pc t0 a0 a1
si
info registers pc t0 a0 a1
si
info registers pc t0 a0 a1
si
info registers pc t0 a0 a1
si
info registers pc t0 a0 a1
```

QEMU 4.1.1 本机观察到 `0x1000 auipc t0,0`；`0x1004 addi a1,t0,32`（DTB 地址为 `0x1020`）；`0x1008 csrr a0,mhartid`；`0x100c ld t0,24(t0)`（得到固件入口 `0x80000000`）；`0x1010 jr t0` 后 PC 为 `0x80000000`。这一段是 QEMU virt 的复位代码，不是 `entry.S`。**你截 `06-复位五条指令.png`：** 重点保留五条单步的 PC/寄存器变化。

继续在 GDB 输入：

```gdb
break *0x80200000
continue
p/x $pc
p/x $sp
p/x $ra
x/4i $pc
```

命中 `kern_entry` 时 PC 为 `0x80200000`，此时入口的 `la` 还没执行，SP 仍是 OpenSBI 阶段的值。**你截 `07-固件交权至内核.png`：** 包含断点命中、PC/SP/RA 和入口反汇编。图注写明控制流 `0x1000 → 0x80000000 → 0x80200000`。

## 5. 单步执行练习 1

保持在 `0x80200000` 断点处：

```gdb
set $old_ra = $ra
p/x &bootstack
p/x &bootstacktop
x/4i $pc
si
si
p/x $sp
p/x &bootstacktop
si
p/x $pc
p/x $ra
p/x $old_ra
```

本次构建中 `la sp,bootstacktop` 展开成两条指令，执行两次 `si` 后 SP 应为 `0x80203000`；第三次 `si` 执行 `tail kern_init`，PC 应为 `0x8020000a`，RA 与 `$old_ra` 相同。**你截 `08-栈与尾调用.png`：** 包含栈上下界、SP 对照、跳转后的 PC/RA。

输入 `continue` 后，终端 A 会打印内核消息。终端 B 按 `Ctrl+C` 中断 GDB，再输入 `detach`、`quit`；终端 A 用 `Ctrl+A`，松开后按 `X` 退出。每次想重新观察 `0x1000` 都必须重启 QEMU。
