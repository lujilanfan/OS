## 从当前分支复核

在已配置交叉编译工具链与 QEMU 的 WSL 中，从本仓库根目录执行：

```bash
cd code
riscv64-unknown-elf-gcc --version | head -n 1
qemu-system-riscv64 --version | head -n 1
make -B -j2
make qemu
```

内核正常启动后应显示 `memory management: best_fit_pmm_manager`、`check_alloc_page() succeeded!` 和 `slub_check() succeeded!`。内核随后进入常驻循环，QEMU 不会自动退出；取得真实终端输出后，按 `Ctrl+A`，松开，再按 `X` 退出。然后运行：

```bash
make grade
```

评分脚本应显示 `check page init: OK`、`check best fit: OK`、`Total Score: 20/20`。`make grade` 会清理构建产物；若之后再运行 `make qemu`，先执行 `make`。最终结果以实际运行的终端画面为准。

现有图 10 没有拍到 `make qemu` 命令及后续两行 `satp` 地址；如果课程要求命令与结果同屏，应由实际操作人补截。截图的操作人和个人贡献由小组按真实情况确认。

## Buddy 与 SLUB 扩展演示

在 WSL 中切换到本次工作区的 `lab2/code`，从默认 Best-Fit 构建切换到 Buddy 时先清理对象文件：

```bash
cd '/mnt/c/Users/12441/Desktop/Book/2026summer/操作系统/lab2/code'
make clean
make -j2 DEFS=-DUSE_BUDDY_PMM
timeout 10s qemu-system-riscv64 -machine virt -nographic -bios default -kernel bin/ucore.img
```

讲解时重点指出 `pmm.c` 的管理器选择、`buddy_pmm.c` 的分阶空闲链表和伙伴合并、`slub.c` 的大小类与大对象页回退，以及 `init.c` 在 `pmm_init()` 后调用的 SLUB 自检。图 12 中应能看到以下四行：

```text
memory management: buddy_pmm_manager
buddy_check() succeeded!
check_alloc_page() succeeded!
slub_check() succeeded!
```

图末尾的 `terminating on signal 15 ... (timeout)` 是命令到时结束常驻 QEMU 的预期提示，不是内核断言失败。`make grade` 只评分 Page Init 和默认 Best-Fit；若想再演示默认配置，运行 `make clean && make -j2` 后启动 QEMU。截图只证明所显示的自检路径运行成功，不能说明并发、性能或所有非法输入均已覆盖。
