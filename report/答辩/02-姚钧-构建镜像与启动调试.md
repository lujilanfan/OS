# 姚钧答辩稿：构建、镜像和 GDB 启动链

> 身份：拟定的练习 2 答辩负责人。实验实际在李潇健的电脑执行；本文是源码与本机结果的学习稿，答辩时不能说自己在另一台电脑执行过或亲自截过图。

## 一、先讲总体架构：做了什么、为什么做、怎样做

**做了什么。** Lab1 把最小内核编译成 RISC-V ELF，再转为裸镜像，使用 QEMU 4.1.1 启动，用 GDB 追踪复位代码、OpenSBI 和内核第一条指令。指导书的两道正式练习是解释 `la sp,bootstacktop`/`tail kern_init`，以及单步观察上电后的首批指令直到 `0x80200000`。没有新增内核函数。

**为什么做。** 一台刚上电的机器不会自动认识 C 源码。链接器要确定代码地址，模拟器要放置机器码，复位代码和固件要把 PC 送进内核。只看到内存里有代码不能证明 CPU 会执行它；只看到 QEMU 窗口有 OpenSBI 也不能证明内核已运行。

**怎样做。** `make` 调交叉编译器、链接器和 `objcopy`；`make qemu` 用原始 `-device loader` 参数预装载镜像；`make debug` 用 `-S -s` 停住虚拟 CPU；GDB 观察 PC、反汇编、寄存器、内存字节和断点。完整控制流是：

```text
源码 → 目标文件 → bin/kernel(ELF, entry=0x80200000) → bin/ucore.img(裸字节)
QEMU 预装载镜像到 0x80200000
PC=0x1000 QEMU virt MROM → PC=0x80000000 OpenSBI
→ PC=0x80200000 kern_entry → 建栈 → kern_init → SBI 字符输出
```

开场应特别说清：QEMU 执行的是宿主机上的模拟器；GDB 连到 QEMU 后看到的是**虚拟 RISC-V guest CPU** 的寄存器和内存，并非宿主 CPU 指令。当前工程的镜像由 QEMU loader 在虚拟 CPU 执行前放入，OpenSBI 做初始化和移交控制权。

`-mcmodel=medany` 允许生成适合当前内核地址的 PC 相对访问；`-nostdinc/-nostdlib` 表示不把宿主 C 运行时当内核依赖；`-ffunction-sections/-fdata-sections` 和 `--gc-sections` 共同让未引用的节在链接时被丢弃；`-g` 留给 GDB 调试。`-fno-stack-protector` 避免引入当前内核没有的栈保护运行时。`HOSTCC/HOSTCFLAGS`、`COPY/MV/AWK/SED/SH/TR/TOUCH` 等是构建辅助变量，不是 guest 内核函数。

### 3.2 `tools/function.mk` 的全部规则生成机制

```make
OBJPREFIX := __objs_                # 分组内部变量前缀。
.SECONDEXPANSION:                  # 规则的依赖项可作第二次展开，供自动建目录。
listf = $(filter $(if $(2),$(addprefix %.,$(2)),%),$(wildcard $(addsuffix $(SLASH)*,$(1))))
# 给定目录和扩展名，找到对应 C/S 文件；空目录自然返回空表。
toobj = $(addprefix $(OBJDIR)$(SLASH)$(if $(2),$(2)$(SLASH)),$(addsuffix .o,$(basename $(1))))
todep = $(patsubst %.o,%.d,$(call toobj,$(1),$(2)))
totarget = $(addprefix $(BINDIR)$(SLASH),$(1))
packetname = $(if $(1),$(addprefix $(OBJPREFIX),$(1)),$(OBJPREFIX))
# 分别计算 .o、.d、bin/目标及分组变量名。

define cc_template
$$(call todep,$(1),$(4)): $(1) | $$$$(dir $$$$@)
	@$(2) -I$$(dir $(1)) $(3) -MM $$< -MT "$$(patsubst %.d,%.o,$$@) $$@"> $$@
$$(call toobj,$(1),$(4)): $(1) | $$$$(dir $$$$@)
	@echo + cc $$<
	$(V)$(2) -I$$(dir $(1)) $(3) -c $$< -o $$@
ALLOBJS += $$(call toobj,$(1),$(4))
endef
# 【重点】每个源文件同时生成头文件依赖 .d 与机器代码 .o，并加入 ALLOBJS。
# $@ 是目标，$< 是第一个依赖；| 后的是先建目录的“仅顺序依赖”。
```

`$` 有多层转义，是因为 `call`、`eval`、二次展开会依次处理变量；答辩不需要背每个美元号，只需准确说明**自动搜源文件、生成 `.d`/`.o`、创建目录、汇总目标**。

```make
define do_cc_compile
$$(foreach f,$(1),$$(eval $$(call cc_template,$$(f),$(2),$(3),$(4))))
endef
# 对每个文件套用 cc_template。
define do_add_files_to_packet
__temp_packet__ := $(call packetname,$(4))
ifeq ($$(origin $$(__temp_packet__)),undefined)
$$(__temp_packet__) :=
endif
__temp_objs__ := $(call toobj,$(1),$(5))
$$(foreach f,$(1),$$(eval $$(call cc_template,$$(f),$(2),$(3),$(5))))
$$(__temp_packet__) += $$(__temp_objs__)
endef
# 【重点】把生成的对象加入 kernel 或 libs 这类 packet；未定义则先初始化。
define do_add_objs_to_packet
__temp_packet__ := $(call packetname,$(2))
ifeq ($$(origin $$(__temp_packet__)),undefined)
$$(__temp_packet__) :=
endif
$$(__temp_packet__) += $(1)
endef
# 允许把已有对象直接放入 packet。
define do_create_target
__temp_target__ = $(call totarget,$(1))
__temp_objs__ = $$(foreach p,$(call packetname,$(2)),$$($$(p))) $(3)
TARGETS += $$(__temp_target__)
ifneq ($(4),)
$$(__temp_target__): $$(__temp_objs__) | $$$$(dir $$$$@)
	$(V)$(4) $(5) $$^ -o $$@
else
$$(__temp_target__): $$(__temp_objs__) | $$$$(dir $$$$@)
endif
endef
# 汇总分组对象和直接对象，为 bin/目标生成依赖；若传入编译器则直接调用。
define do_finish_all
ALLDEPS = $$(ALLOBJS:.o=.d)
$$(sort $$(dir $$(ALLOBJS)) $(BINDIR)$(SLASH) $(OBJDIR)$(SLASH)):
	@$(MKDIR) $$@
endef
# 由 .o 推导 .d；统一生成必须的 obj/bin 目录规则。
# 文件尾的 cc_compile/add_files/add_objs/create_target/read_packet/add_dependency/finish_all
# 是对上面 define 宏的 eval/call 包装；Makefile 通过它们生成真实规则。
```

## 四、练习 2：五条复位指令逐条答

本次 QEMU 4.1.1 的有效复位指令为：

| PC | 指令 | 现场讲解 |
|---|---|---|
| `0x1000` | `auipc t0,0` | 用当前 PC 构造基址，执行后 `t0=0x1000`。 |
| `0x1004` | `addi a1,t0,32` | 把设备树 DTB 的地址 `0x1020` 放入 `a1`；传的是地址。 |
| `0x1008` | `csrr a0,mhartid` | 把 hart ID 放入 `a0`，单核本机为 0。 |
| `0x100c` | `ld t0,24(t0)` | 从复位向量旁的常量区域取出 OpenSBI 入口 `0x80000000`。 |
| `0x1010` | `jr t0` | 跳至 OpenSBI；之后固件初始化并交给内核 `0x80200000`。 |

`0x1018` 一带是复位向量的常量，不把它说成按顺序执行的指令。`0x1020` 是本次 DTB 地址；它不是“下一个 PC”。QEMU 8.2.2 的复位向量多了参数传递，不能套用本页五条顺序和寄存器值。老师问“这些指令主要完成什么”：答准备 hart ID 和设备树地址，取得固件入口并跳转；不在这一阶段从磁盘读内核。

现场命令在[本机操作单](../操作步骤与截图说明.md)。核心是 `gdb-multiarch bin/kernel` → `target remote localhost:1234` → `x/5i $pc` → 逐条 `si` → `break *0x80200000` → `continue`。初始 `0x1000` 时运行 `x/16bx 0x80200000`，对照 `od -An -tx1 -N16 bin/ucore.img`。镜像已在内存，但最终进入内核还须用断点证明。写监视点只能观察设置之后、入口 4 字节的 guest 写，不会追溯捕获 QEMU 启动前的预装载。

## 五、老师可能继续追问

1. **ELF 和 IMG 有什么不同？** ELF 有入口、节/程序段、符号及调试信息；IMG 是供固定地址放置的裸字节。GDB 用 ELF，QEMU loader 用 IMG。
2. **`-device loader` 与 `-kernel` 能否混为一谈？** 不能。QEMU 8.2.2 曾出现前者放入字节但默认固件未进入内核，后者能进入；本实验主证据是 QEMU 4.1.1 的原 Makefile 参数。
3. **`-S`、`-s` 是什么？** 前者暂停 CPU，后者开 GDB 远程端口 1234。
4. **为何 GDB 的 `file bin/kernel` 不代表加载 ELF 到 guest？** 这里读取的是符号/调试信息；内存镜像由 QEMU loader 放置。
5. **如何证明 CPU 最终真的到内核？** 内核入口断点命中且 PC=`0x80200000`，随后 SP 改变和内核打印。
6. **为什么没有 `make grade` 截图？** 当前树缺 `tools/grade.sh`，不能声称官方评分通过；由实际操作人向助教确认脚本或替代验收。
7. **现在的版本就是 2026 正式基线吗？** 还不能保证。当前精简包与指导书示例树不同，必须向助教核对。
