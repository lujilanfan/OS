## 一、先讲总体架构：做了什么、为什么做、怎样做

**做了什么。** 本次 Lab1 用现有最小 ucore 源码构建 RISC-V ELF `bin/kernel` 和裸镜像 `bin/ucore.img`，在 QEMU 4.1.1 中启动，在 GDB 里从复位地址追踪到内核入口，回答指导书的两道练习。没有新增调度、进程或内存分配代码。

**为什么做。** 一段 C 代码不能直接在“刚上电”的机器上运行：CPU 必须先找到指令，固件要建立运行环境，内核入口要设置自己的栈，打印信息还需调用固件服务。这个实验把这些前提从概念变为地址、寄存器、符号和终端输出。

**怎样做。** 交叉编译器把 C/汇编变成 RISC-V 目标文件；链接脚本固定入口及内存布局；`objcopy` 产生裸镜像；QEMU 在虚拟 CPU 启动前将镜像预装载到 `0x80200000`。QEMU 的 MROM 复位代码从 `0x1000` 跳至 `0x80000000` 的 OpenSBI；OpenSBI 初始化后将控制权交给 `0x80200000` 的 `kern_entry`；入口设置 SP、跳入 C 函数；C 函数通过 SBI 打印并死循环。用原 `make qemu` 和 `make debug` + GDB 验证。三人均应背得出：

```text
源码 → bin/kernel(ELF, 调试/符号) → bin/ucore.img(裸镜像)
QEMU 预装载 0x80200000；guest PC 0x1000(MROM) → 0x80000000(OpenSBI)
→ 0x80200000(kern_entry) → 0x8020000a(kern_init) → cprintf → SBI → 终端
```

这三个地址属于不同阶段。`0x1000` 不等于 OpenSBI；`0x80000000` 是本机默认 OpenSBI 的入口；`0x80200000` 是本次内核入口。指导书早期页面用“OpenSBI 加载”概括过程，但第 64 页和本工程 `-device loader` 参数表明实际预装载由 QEMU 完成，OpenSBI负责最终交权。

## 二、我的答辩范围及详细架构

负责讲解指导书练习 1：`la sp,bootstacktop` 与 `tail kern_init` 分别做什么、为什么做。需要把四个文件连成一条因果链：

| 源码 | 作用 | 可观察结果 |
|---|---|---|
| `kern/mm/mmu.h`、`memlayout.h` | 定义页大小、页位数和内核栈大小 | `4096 × 2 = 8192` 字节 |
| `kern/init/entry.S` | 申请栈，设置 SP，尾跳转 C 入口 | `sp=0x80203000`、PC 到 `kern_init` |
| `tools/kernel.ld` | 固定 ELF 入口、起始地址和节布局 | ELF 入口 `0x80200000`；栈在数据段 |
| `kern/init/init.c` | 清零 BSS 区间、打印、死循环 | 打印 `(THU.CST) os is loading ...` |

内存关系在本次编译中为 `bootstack=0x80201000`，`bootstacktop=0x80203000`，中间连续 `0x2000` 字节；栈由高地址向低地址增长。`edata=end=0x80203008`，所以清零长度是 **0**，不可宣称本次实际清零了非空 BSS。

## 三、逐段带注释读负责的源码

以下注释是答辩解释，原始源码并未修改。`【重点】` 是最可能被追问的地方。

### 3.1 页与栈的常量

```c
// kern/mm/mmu.h：一页是 4096 = 2^12 字节。
#define PGSIZE 4096
#define PGSHIFT 12

// kern/mm/memlayout.h：内核栈用两页；这里只定义大小，实际空间在 entry.S 申请。
#define KSTACKPAGE 2
#define KSTACKSIZE (KSTACKPAGE * PGSIZE) // 8192 字节
```

`PGSHIFT` 用在 GAS 的 `.align PGSHIFT`，这里是按 `2^12=4096` 字节对齐；它不是把栈“扩大 12 倍”。头文件里其余部分是 include guard，用来避免重复包含。

### 3.2 完整入口汇编 `kern/init/entry.S`

```asm
#include <mmu.h>         # 引入 PGSIZE、PGSHIFT。
#include <memlayout.h>   # 引入 KSTACKSIZE。

    .section .text,"ax",%progbits  # 指令放可分配、可执行的 .text。
    .globl kern_entry            # 把入口符号导出给链接器/GDB。
kern_entry:                     # 链接脚本 ENTRY 指向这里。
    la sp, bootstacktop         # 【重点】把栈顶符号的地址放入栈指针，不是读取该地址内存的值。

    tail kern_init              # 【重点】尾跳转到 C 入口，不写新的返回地址 ra。

.section .data                  # 栈作为已分配的数据段空间。
    # .align 2^12              # 原文件里的注释；真正执行的是下一行。
    .align PGSHIFT              # 地址按 4096 字节对齐。
    .global bootstack           # 导出栈底符号，便于链接/调试。
bootstack:
    .space KSTACKSIZE           # 预留 8192 字节，符号 bootstack 指向低地址端。
    .global bootstacktop        # 导出栈顶符号。
bootstacktop:                   # 不另占一个字节，标签指向预留空间结束位置。
```

`la` 是伪指令，汇编/链接后可能展开多条机器指令。本次反汇编：

```asm
0x80200000 <kern_entry>:   auipc sp,0x3  # PC 加偏移，得到栈顶所在附近的地址。
0x80200004 <kern_entry+4>: mv sp,sp      # 本次重定位的低位偏移恰为 0，所以表现为原值移动。
0x80200008 <kern_entry+8>: j 0x8020000a <kern_init> # tail 的实际跳转。
```

不要死记“`la` 永远是 `auipc+mv`”：具体机器码受链接布局、重定位和工具链影响，稳定含义是把 `bootstacktop` 地址放入 SP。刚命中入口断点时，SP 还是固件的 `0x8001bd80`；对前两条指令执行两次 `si` 后变为 `0x80203000`。尾跳之后 PC 变为 `0x8020000a`，RA 仍是 `0x80000a02`。`tail` 与 `call` 的区别是前者不生成新的返回地址；`kern_init` 声明为 `noreturn` 且最后死循环，不需要回到入口汇编。

### 3.3 完整链接脚本 `tools/kernel.ld`

```ld
/* 告诉链接器输出 RISC-V ELF；不是 QEMU 的装载操作。 */
OUTPUT_ARCH(riscv)
/* 【重点】ELF 入口符号由此指定。 */
ENTRY(kern_entry)

BASE_ADDRESS = 0x80200000; /* 本实验约定的内核起点。 */
SECTIONS {
    . = BASE_ADDRESS;     /* 定位计数器从该地址开始排布节。 */
    .text : {
        *(.text.kern_entry .text .stub .text.* .gnu.linkonce.t.*)
        /* 收集所有目标文件的代码节，先把入口放在开头。 */
    }
    PROVIDE(etext = .);   /* 标记代码节之后的位置。 */
    .rodata : {
        *(.rodata .rodata.* .gnu.linkonce.r.*)
        /* 收集只读常量，如要打印的字符串。 */
    }
    . = ALIGN(0x1000);    /* 【重点】将后续数据节起点向上对齐到 4096 的倍数。 */
    .data : {
        *(.data)
        *(.data.*)         /* 收集全局已初始化数据，栈空间也在本工程此节。 */
    }
    .sdata : {
        *(.sdata)
        *(.sdata.*)        /* RISC-V 的小数据节。 */
    }
    PROVIDE(edata = .);   /* 已初始化数据的末端。 */
    .bss : {
        *(.bss)
        *(.bss.*)
        *(.sbss*)          /* 收集未初始化数据；通常不占 ELF 文件中的初始化字节。 */
    }
    PROVIDE(end = .);     /* 内核已分配节的末端。 */
    /DISCARD/ : {
        *(.eh_frame .note.GNU-stack) /* 丢弃本实验不需要的异常帧/注记。 */
    }
}
```

`ENTRY`、`BASE_ADDRESS`、QEMU `addr=0x80200000` 三者必须匹配。`ALIGN(0x1000)` 是 4096 字节对齐，不是“2 的 0x1000 次方”。ELF 的节、程序段、入口和符号可用 `readelf`/`nm` 查询；`ucore.img` 是 `objcopy -O binary` 生成的裸镜像，没有 ELF 头、节表、调试符号。不要把“清零 BSS 的通用代码”误说成“本次有非空 BSS”。

### 3.4 完整 C 入口 `kern/init/init.c` 与清零函数

```c
#include <stdio.h>  // cprintf 的声明，来自内核自己的 stdio，不是宿主 glibc。
#include <string.h> // memset 声明。
#include <sbi.h>    // 当前文件没有直接调用 SBI；源文件保留了这个包含。
int kern_init(void) __attribute__((noreturn)); // 告诉编译器函数不会返回。

int kern_init(void) {
    extern char edata[], end[];         // 从链接脚本取得 BSS 前后边界。
    memset(edata, 0, end - edata);      // 【重点】本次两个地址同为 0x80203008，n=0。
    const char *message = "(THU.CST) os is loading ...\n";
    cprintf("%s\n\n", message);       // 交由格式化层、console、SBI 输出。
    while (1)                        // 没有退出/调度功能，打印后一直停在内核。
        ;
}

// libs/string.c 中本次可能调用的 memset 核心：
void *memset(void *s, char c, size_t n) {
#ifdef __HAVE_ARCH_MEMSET
    return __memset(s, c, n); // 若提供架构优化实现则调用；当前基线未启用。
#else
    char *p = s;
    while (n-- > 0) *p++ = c; // 逐字节填充；n=0 时循环体不执行。
    return s;
#endif
}
```

`while (1)` 解释为什么看到打印以后 QEMU 不自动退出。`noreturn` 是编译器属性，不是产生“自动退出”的指令。源码里的 `memset` 写法是通用初始化步骤，本次因为边界相等而没有实质写入。

## 四、现场怎样证明，不只会背结论

在 `code/` 用 `riscv64-unknown-elf-readelf -h bin/kernel` 看 ELF Entry；用 `riscv64-unknown-elf-nm -n bin/kernel` 看 `bootstack`、`bootstacktop`、`edata`、`end`；用 `riscv64-unknown-elf-objdump -d bin/kernel` 看入口反汇编。在 GDB 命中 `break *0x80200000` 后先记录 SP/RA，再两次 `si` 核对 SP=`&bootstacktop`，第三次 `si` 核对 PC=`kern_init` 且 RA 不变。具体可直接按[本机操作单](../操作步骤与截图说明.md)第 4、5 节做，截图由实际操作人保存。

## 五、老师可能继续追问

1. **为什么在 C 前设置 SP？** C 的函数调用、局部对象和寄存器保存依赖有效栈；固件阶段的栈不应被当作长期内核栈。
2. **为什么用栈顶，不用 `bootstack`？** RISC-V 约定栈向低地址增长；初始化为空栈时 SP 放高地址端。
3. **`la` 读取的是栈顶内容吗？** 不是，取的是符号地址；若误读内容，SP 可能指向无效位置。
4. **`tail` 与 `call` 的 RA 差别？** `call` 写入返回地址，`tail` 只跳转；本实验的 C 入口不返回。
5. **为什么断在 `0x80200000` 时 SP 还不是 `0x80203000`？** 断点停在指令执行前，先有固件 SP；执行两条展开指令后才改变。
6. **BSS 确实被清零了吗？** 源码具备清零逻辑，本次 `end-edata=0`，不能声称实际清零了非空区域。
7. **为何 `kern_init` 地址是 `0x8020000a`，不是 `0x8020000c`？** RISC-V 的压缩指令可占 2 字节，`j` 本次为压缩编码；看实际反汇编而不是固定按 4 字节递增。
8. **只会自己的部分够吗？** 不够。必须还能回答 QEMU 预装载、MROM→OpenSBI→内核、ELF/IMG 区别、SBI 输出和缺失 grade 脚本。
