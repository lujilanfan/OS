# Lab1 图像材料说明

当前目录有 `1.png`—`7.png`，由远端 `lab1` 分支的 `16cc7a8` 提交加入。它们是终端画面，不是此前已删除的自动取证文件。

| 文件 | 画面中可核查的内容 | 不能据此推出的结论 |
|---|---|---|
| `1.png` | `make clean`、`make` 与 `bin/kernel`、`bin/ucore.img` 产物 | 不能证明 QEMU/GDB 版本；产物时间显示为 10 月 8 日 19:09 |
| `2.png` | `make qemu` 后出现 OpenSBI v0.4 和内核输出；`activate.sh` 显示 `toolchain-10.2.0` | 不能据 OpenSBI 版本推断 QEMU 可执行文件版本 |
| `3.png` | GDB 在 `0x1000` 显示五条复位指令 | 未完整展示每条指令执行后的寄存器值 |
| `4.png` | 单步后 PC 从 `0x1010` 跳到 OpenSBI 的 `0x80000000` | 不展示固件内部全部初始化过程 |
| `5.png` | 断点命中 `kern_entry`，PC 为 `0x80200000` | 不展示镜像被写入内存的瞬间 |
| `6.png` | `sp=0x80203000`，与 `&bootstacktop` 相等 | GDB 对同一地址显示另一符号名，不能只凭符号显示判断栈顶 |
| `7.png` | `tail` 后 PC 到 `kern_init`，`ra` 保持 `0x80000a02` | 不证明后续所有内核功能 |

图片中可见的终端会话为 `jun@yaojun:~/os-lab/projects/lab1`。这与报告所述的李潇健 WSL 路径、GCC 13.2.0 环境不同；终端用户名也不能单独证明实际操作者身份。引用这些图片时，应由实际操作者核实机器环境、QEMU/GDB 版本、日期与运行时源码提交号，再写准确图题。不得把它们直接标为另一台电脑的实测结果，也不得借图片声称 `make grade` 已通过。

正式指导书 Lab1 的 `watch *0x80200000` 是观察建议。当前七张图没有监视点输出、ELF 头与镜像字节对照；如需在报告中将这些观察作为有图证的实测，应按[操作步骤与截图说明](../操作步骤与截图说明.md)重新运行并保存真实画面。
